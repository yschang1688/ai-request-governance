# AI Gateway PoC：認證、授權與去識別化 — Requirements（L2，預先登記）

> 狀態：2026-10-19 作者決定開規格，**待核准後才動手**。本檔的門檻在寫任何程式前 commit；實作中不得修改門檻，只能在報告裡照實記錄未達。
> 來源：AI 需求管理流程的設計討論中，被追問認證（AuthN）與授權（AuthZ）怎麼落地，事後畫了一張「AI Gateway：認證、授權與去識別化」示意架構圖。本 PoC 把那張圖的每一層做成「故意去弄、應該被擋」的測試。

## 要回答的問題

示意架構圖上的每一層，是否真的擋得住它聲稱要擋的事？具體是：

1. 沒有合法身分的請求，進不了 Gateway。
2. 身分合法但權限不夠，拿不到超出等級的資料。
3. 模型與日誌看不到原始個資，使用者拿回的回應仍是還原後的內容。
4. AI Agent 代表使用者時，權限不會比使用者本人大。
5. 查日誌的人自己也留紀錄；用量異常會被標出。

## 範圍

**含**：本機 IdP（Keycloak，代替 Entra ID）、Gateway（認證、ABAC 授權、去識別化、稽核、用量監控）、內部 API（合成工單）、Agent 兩種 OAuth 流程（Client Credentials、Token Exchange 代表使用者）、地端模型（Ollama qwen3.5:9b）、自動化測試與報告、簡報一頁。

**不含**（報告須照列為邊界）：
- 真正的 Entra ID 與條件式存取；Entra 的 On-Behalf-Of 是微軟流程，本 PoC 用同一套標準（RFC 8693 Token Exchange）在 Keycloak 上驗證**設計**，不宣稱「在 Entra 上跑過」。
- MFA 只做**手動示範一次**（Keycloak 設 TOTP 必要），不列入自動化門檻：自動化測試用密碼直取 token（Direct Grant）只為了測試方便，正式環境應用授權碼＋PKCE。
- 姓名偵測：格式規則認得身分證、手機、email、統編，**認不得自由文字裡的姓名**。本 PoC 不解決，報告照實寫。
- 效能、高可用、金鑰輪換的實際演練、正式 SIEM 串接。

## 資料

全部合成，沿用 `ticket-sensitivity` 的合成工單（帶紅黃綠燈號）作為內部 API 的資料；使用者、部門、專案、資料等級都是虛構。沒有任何真實個資或公司資料。

## 預先登記門檻

每一條都附「反向檢核」：把對應的檢查拿掉（以設定旗標關閉）重跑同一組測試，該測試**必須轉紅**；反向檢核沒轉紅，代表測試沒測到東西，該門檻視為未達。

| # | 層 | 測試 | 門檻 |
|---|---|---|---|
| G1 | 認證 | 無 token、竄改簽章、`alg:none`、過期、`aud` 不符、`iss` 不符，6 種各 1 次 | 6/6 回 401 |
| G2 | 認證 | 合法 token 正常通過 | 3 個使用者 3/3 回 200 |
| G3 | 授權 | 3 個使用者 × 3 個等級 × 2 個專案 = 18 個組合，對照預期矩陣 | 18/18 與矩陣一致（越權 0、誤擋 0） |
| G4 | 去識別化 | 40 則含格式個資的提問（身分證、手機、email、統編混合），模型端收到的內容 | 原始個資出現 0 次 |
| G5 | 去識別化 | 同 40 則，使用者收到的回應中，模型有引用到的代碼 | 100% 還原成原值 |
| G6 | 稽核 | 跑完 G1–G5 後掃整份稽核日誌 | 原始個資出現 0 次；每個請求都有一筆（筆數＝請求數） |
| G7 | 稽核 | 非稽核員查日誌；稽核員查日誌 | 前者 403；後者 200，且「查日誌」本身新增一筆紀錄 |
| G8 | 用量 | 先送 30 分鐘份量的正常節奏（壓縮時間重播），再送 10 倍突增 | 正常段警示 0 次；突增段 ≥1 次 |
| G9 | Agent（服務帳號） | ticket-agent 讀綠燈工單；讀黃／紅燈工單；呼叫寫入 API | 綠 200；黃紅與寫入皆 403 |
| G10 | Agent（代表使用者） | Agent 以 u-green、u-red 的 token 交換後讀紅燈工單；Agent 不帶使用者 token 直接要求交換 | u-green 403、u-red 200；無使用者 token 的交換被 IdP 拒絕 |
| G11 | 端到端 | 3 則提問經 Gateway 送進地端 9B 並拿回回答 | 3/3 成功，模型端紀錄無原始個資 |

**整體判定**：G1–G10 全達才可以對外說「示意架構的每一層都實測擋得住」；任一未達，簡報與報告照實寫哪一層、差多少。G11 是可行性展示，不影響判定。

## 安全守則

- 所有金鑰、client secret 只存在 `.env.local`（gitignored）或由 realm 匯入時產生；repo 不放任何 secret。realm 匯出檔若含 secret，提交前改成佔位字串。
- Keycloak 只綁 `127.0.0.1`，不對外開 port。
- 測試資料全為合成；不連任何外部服務（Ollama 為本機）。
