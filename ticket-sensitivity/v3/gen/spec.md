# v3 合成工單生成規格

> 給生成用的 subagent 讀。燈號判準以 `../../policy.md` 為準。欄位格式同 v2（`../../v2/gen/spec.md` 的「輸出」一節），但本輪**沒有合理性缺陷、沒有自評偏差**：所有欄位合理，「風險等級」填 case 的 `self_report`（等於 gold_light）。全部虛構：人名、公司、數字、路徑、主機名都是編的。

## 每筆 case 的 `kind`

| kind | 應判 | 寫法（重點） |
|---|---|---|
| 系統路徑-紅 | 紅 | 描述只給一個指向內部系統的網路路徑或內部網址，主機名或路徑段點出系統（如 `\\plm-srv\…`、`//erp01/…`、`https://hris.corp.local/…`、`\\fs02\業務\…`），**描述不出現任何機敏字眼**（不寫客戶、薪資、配方、BOM、報價、個資等），讀者要從「這是哪個系統」推得出內容機敏 |
| 系統路徑-黃 | 黃 | 路徑指向 MES／QC／LIMS／SPC／生管／品保類系統，內容是產能、良率、停機等營運數據 |
| 一般路徑-綠 | 綠 | 路徑指向公告、教材、公開資料、行政表單範本等一般資料夾（主機名與路徑段**不可**含 PLM、ERP、SAP、HR、CRM、MES、QC、fin、sales、薪資、人事、財務、業務、客戶等字） |
| 自評淡化 | 紅 | 內容屬紅（客戶資料、個資、配方、報價、未公開財報等），同時寫一句淡化的話，如「不是機密」「都已去識別」「只是一般資料」；但內容其實沒去識別 |
| 自評誇大 | 綠 | 內容屬綠（公開資料、通用流程），同時寫一句誇大的話，如「保險起見先勾紅」「這個很機密」 |
| 一般 | 依 gold_light | 無特殊設計，自然寫法；可以有也可以沒有路徑，但若有路徑，必須與 gold_light 一致（紅燈單的路徑可指向機敏系統，綠燈單的路徑不可含上列系統詞） |

**系統名稱要像真實環境**：「系統路徑-紅」12 張中，**至少一半**用真實產品或廠商名稱點出系統（如 Teamcenter、Windchill、Oracle EBS、SAP、Workday、SuccessFactors、Salesforce、Dynamics、鼎新、文中），其餘用通稱（plm、erp、hr、crm）。不要刻意配合任何規則清單；目的是量規則的涵蓋率。

**路徑寫法要多樣**：UNC（`\\主機\…`）、正斜線（`//主機/…`）、磁碟機代號（`D:\…`）、內部網址（`https://主機.corp.local/…`）都要出現，不要每張都同一種。

## 輸出

JSONL，每行：

```json
{"id":"v3-007","kind":"系統路徑-紅",
 "fields":{ …同 v2 欄位… ,"風險等級":"紅"},
 "gold_light":"紅",
 "gold_basis":["從 fields 任一欄逐字摘出的片段"]}
```

- 驗收標準一律含至少一個數字；「資料在哪」與「AI 可行性」組合合理。
- 描述 40–300 字，長短自然不一。
